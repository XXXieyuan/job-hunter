## Checkpoint Engine

The project uses a general-purpose checkpoint engine (`.coding-agent/engine/`) to drive its development pipeline. The engine ensures no step is skipped through code-driven state machines, not LLM context.

### Engine Commands

| Command | Purpose |
|---------|---------|
| `node .coding-agent/engine/checkpoint-runner.mjs --phase N` | Run phase N |
| `node .coding-agent/engine/checkpoint-runner.mjs --phase N --resume` | Resume from last checkpoint |
| `node .coding-agent/engine/checkpoint-runner.mjs --phase N --status` | Instant progress check |
| `bash .coding-agent/engine/checkpoint-ctl.sh --phase N status` | Operator status |
| `bash .coding-agent/engine/checkpoint-ctl.sh --phase N skip <id>` | Skip a checkpoint |
| `bash .coding-agent/engine/checkpoint-ctl.sh --phase N force-accept <id>` | Force-accept a review |

### Engine Architecture

```
.coding-agent/engine/
  checkpoint-runner.mjs      Core: state machine, worker loop, executor dispatch
  checkpoint-lib.mjs         Utilities: atomic I/O, locks, events, progress
  checkpoint-planner.mjs     Graph: build, validate, dynamic expand
  checkpoint-ctl.sh          Operator: resume/skip/abort/force-accept
  executors/
    agent-executor.mjs       Claude CLI subprocess (claude --print)
    script-executor.mjs      Node.js/Python scripts
    file-executor.mjs        File existence checks
  registry/
    phase*.json              Checkpoint graphs per phase
    phase*-prompts.json      Instruction templates per phase (generic)
```

### Prompt Layering (Three Layers)

```
1. Generic base     — engine/registry/phase{N}-prompts.json (universal rules)
2. Auto overlay     — phase{N}/prompts-project.json (generated by P4.0, may be overwritten)
3. Manual overlay   — phase{N}/prompts-project-manual.json (hand-written, never auto-overwritten)
```

Arrays are appended at each layer. Manual overlay wins last.

### Self-Repair (Phase 6)

The engine includes an automatic self-repair loop for code execution:
- **First run**: `execute-batch` (3-phase: understand → implement → verify)
- **After review revision**: auto-swaps to `fix-batch` (targeted fixes only) + `re-review-batch` (verify fixes + regression check)
- **Ripple rule**: changing a constant/error code greps all references and updates them together
- **No hard retry limit**: continues as long as fix agent makes progress. Blocks on stagnation (same failures 3x) or reviewer `blocked` verdict.
- **Resume guard**: only infra issues (rate limit, credentials) can be resumed. Code bugs must be fixed.

## Architecture

Express.js 5 web app for job hunting — scrapes job listings, scores them against user resumes using AI, generates cover letters, and tracks applications.

**Stack:** Node.js + Express 5 / better-sqlite3 (WAL mode) / EJS templates (ejs-mate layouts) / OpenAI-compatible API (pluggable provider) / Python curl_cffi (scraping) / Winston (logging)

**Key decisions (validated through pipeline):**
- DOCX-only resume upload (PDF removed — BA validated no persona needs it)
- English-only cover letters (Chinese removed — not in application workflow)
- Browse-first: job listing works without auth
- 4-signal scoring: semantic 40% + keyword 30% + role 20% + location 10%

### Layers

- **`src/routes/`** — HTTP handlers. 7 modules: jobs, admin, auth, resume, application, coverLetter, scoreFeedback.
- **`src/services/`** — Business logic: scoring, analysis, cover letter, scraper, auth, background queue, deduplication, visa, resume parser.
- **`src/repositories/`** — Data access layer (14 repos). Prepared statements, FTS5 search.
- **`src/middleware/`** — Auth (session-based), CSRF, rate limiting, file validation (DOCX magic bytes only), Zod validators.
- **`views/`** — EJS templates. Partials in `views/partials/`. Bilingual UI (EN/ZH) via `src/locales/*.json`.
- **`public/`** — Static CSS/JS.
- **`scrapers/`** — Python curl_cffi scrapers: Seek, APSJobs (Aura API), LinkedIn (best-effort).

### Database

SQLite in `./data/job-hunter.sqlite`. Migrations in `src/db/migrations/`. FTS5 virtual table `jobs_fts`. Key tables: jobs, resumes, users, sessions, job_fit_scores, cover_letters, applications, analysis_runs, scraper_runs, companies, duplicate_groups, score_feedback.

### Auth Model

Session tokens in `jh_session` httpOnly cookie (7-day max age). User roles: `user` and `admin`. Admin routes require `requireAdmin` middleware scoped to `/admin` paths. CSRF via Origin header validation.
